# The vault data contract

A second brain that an agent maintains at night only works if every note is machine-readable in the
same way. These rules are small on purpose: each one removes a class of ambiguity that otherwise
makes automated edits unsafe. `audit.mjs` checks them, `normalize.mjs` and `fix-links.mjs` repair
them, `vault-writer.mjs` never produces a violation.

## Rules

| # | Rule | Rationale |
|---|------|-----------|
| 1 | **Frontmatter on every note** (YAML between `---` lines). | Tools can read metadata without parsing prose. |
| 2 | **`tags` is a YAML block list** (`tags:` then `  - tag` lines), never `[a, b]`. | One format means one parser; mixed formats silently drop tags in indexes and searches. |
| 3 | **`created` and `updated` on every note** (`YYYY-MM-DD`). | Lets the night shift compute "what changed" and spot stale notes without trusting file mtimes (sync tools rewrite them). |
| 4 | **H1 = filename, exactly.** Journal notes, root notes, `README` and `generatedNotes` are exempt. | Links are by filename; a title that differs from the filename makes agents create links to notes that do not exist. |
| 5 | **Old titles go in `aliases`.** When an H1 is aligned to the filename, the previous title is kept as an alias. | Nothing a human searched for is lost, and alias links still resolve. |
| 6 | **No `[[link]]` to a missing note.** A file, script or tool name that is not a note is written as `` `code` ``. | A broken link is a lie in the graph: it looks like knowledge but leads nowhere. |
| 7 | **Projects carry `status:` (active / paused / done) and `deadline:`.** | A project without an end is an area; the fields make weekly reviews and archiving mechanical. |
| 8 | **PARA roles are respected** (see below). Nothing is written at the vault root except the allowed files (`HOME.md`, `README.md` by default). | Every note has one obvious home, so an agent can file without guessing. |
| 9 | **Inbox stays small** (`inboxMax`, default 10) and **fresh** (`inboxMaxAgeDays`, default 7). Automated captures never go to the inbox; give them their own resource folder. | The inbox is a pass-through, not a warehouse. An inbox of hundreds is where notes go to die. |
| 10 | **Templates are never edited by tools**, and notes regenerated by a pipeline (`generatedNotes`) are linked *to*, never written *into*. | Edits to generated notes are overwritten on the next pipeline run; edits to templates propagate everywhere. |

## PARA roles

| Folder (default name) | Role | Written when |
|---|---|---|
| `0 - Inbox` | Raw captures | Quick capture, to be triaged |
| `1 - Projects` | Goal + deadline | A structured effort with an end |
| `2 - Areas` | Ongoing responsibilities | Updating a permanent domain |
| `3 - Resources` | Reusable knowledge, one idea per note | Knowledge worth keeping, rephrased |
| `4 - Archives` | Inactive material | A project is done |
| `Journal` | One note per day, `YYYY-MM-DD.md` | Daily log and the night shift report |
| `Templates` | Note templates | Never by tools |

Folder names, per-folder tags and limits are configurable in `vault.config.json`
(see `vault.config.example.json`).

## Maintenance lock

Before any mass edit (`normalize.mjs --apply`, a migration script), create
`.nightshift/maintenance.lock` in the vault. `backup.mjs` and the nightly runner both skip while it
exists, so no half-migrated snapshot is committed and no agent edits notes mid-migration.
Remove it when done.
